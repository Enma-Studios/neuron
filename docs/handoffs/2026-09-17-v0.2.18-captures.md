The result shape, for a host:

- `result.captures`: `[%{url, retrieved_at, content_hash, markdown}]`, once each, exactly the
  pages the returned leads' claims cite.
- Each claim in `lead.evidence` gains `"content_hash"`; the page is `{url, content_hash}`.
- Each `contact_channels` entry gains `evidence: [claim]`, the claim the channel was observed from.
- `retrieved_at` is the Snapshot's `fetched_at`, now written on every read of those bytes.
  A Snapshot not read since v0.2.18 has `nil` until its page is read again.

## Decisions
- Pages are read from the graph at `:finish`, not collected from this run's children: a lead's
  evidence can come from pages read in an earlier run.
- A capture is keyed by `{url, content_hash}`. Identical bytes on two URLs (two 404 pages) are
  two captures.
- `fetched_at` on a Snapshot is overwritten on each read, so `retrieved_at` is the last read of
  those bytes, not the first. That is what lets a Snapshot from before this release gain it.
- The outreach prompt now renders every lead whole (`limit: :infinity`). With a live model this
  is more prompt tokens per draft call, and it is what the model needed to cover every person.
