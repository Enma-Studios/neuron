# Handoff: v0.2.7

One change, two defects, both found by a four second repro on neureni#22.

| PR | Change |
| --- | --- |
| [#28](https://github.com/Enma-Studios/neuron/pull/28) | Name the intake step that failed, and stop navigation exiting |

**Intake told the host the wrong thing, then discarded its answers.** Every step of the intake
chain reported as `:url_unavailable`, on sites that answered 200, because one `with` sat under
one error clause and `scrape_answers/2` collapsed seven steps into one error before that clause
even saw it. The branch then returned all eight questions and threw the caller's answers away,
which is the symptom that was reported: answer all eight, get the identical eight back.

Each step names itself now, and a scrape failure no longer discards answers. Scraping fills
what is missing; it was never meant to be a precondition for what was supplied.

**A navigation wait exited instead of returning.** `visit_and_wait/3` discards the timeout it
is given and waits 30 seconds on a `GenServer.call`, which exits. An exit is not an exception,
so no `with` matched it and no `rescue` saw it, and a slow page killed its caller rather than
failing the fetch. Navigation now uses Neuron's own readiness poll at the caller's timeout and
returns a tagged error.

## What is not claimed

**The hang itself did not reproduce.** Three separate fetches and four consecutive visits on
one session all completed with a profile. Session reuse alone does not do it, nor repeated
navigation to the same URL, nor a redirecting URL. The fix does not depend on the cause: a hang
is now a tagged error at the caller's timeout rather than an exit at a hardcoded 30 seconds. If
the repro names a URL, the cause itself is still findable.
