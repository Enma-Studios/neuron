# Handoff: v0.2.0

Six merged changes against the findings the Neureni spike recorded on 2026-09-10, and the
tag. Every one has a test, a handoff, and a merged PR reviewed by Rusty.

Before this release, a Neuron run against Enma's real brief on the engine configuration the
host is required to use ingested **nothing at all**: no organizations, no sources, no claims,
no ingestion children. It now ingests real prospect companies from that same brief and
configuration.

**#44, browser sessions are always stopped.** Cleanup ran only where a caller reached an
`after` block, so an Oban cancellation, a fleet task exiting rather than raising, or a
release call on an already dead connection process each left a billed cloud browser running
until the provider's own timeout. Every session is now registered against the process that
opened it in a supervised `Neuron.Browser.Sessions` and stopped when that owner goes down,
when the caller closes it, or on application shutdown, with the remote stop running first so
losing the local process cannot skip it. `mix neuron.browser.sweep` is the operator backstop.

**#43, discovery works on public engines.** Four causes, all found by running one instrumented
round rather than by reading the code. Bot walls were invisible because `orchestrate/2` never
called `blocked?/1` or `gated?/1`, so Google's interstitial and DuckDuckGo's anomaly modal
read as engines that honestly found nothing. The planner still demanded LinkedIn and X
coverage when those engines were switched off, aiming the one working engine at a platform
whose pages need an account. The harvest prompt preferred profile URLs over pages a company
publishes itself. And harvested URLs were the search engine's own redirect wrappers, so
ingesting one fetched DuckDuckGo and recorded DuckDuckGo as the organization.

**#38, the model fetch lands where the loader reads.** The fetch task resolved its target
against the working directory and the loader against Neuron's application directory. Those
agree only standalone, so as a dependency the documented setup always ended in `embedding
model missing`, naming the command that had just succeeded. One function owns the answer now,
and a model in the wrong `priv` is reported differently from one never fetched.

**#41, a login gate is a skipped engine.** The round-level condition landed in #43, which
could not meet its acceptance without it. This added the classification a host renders from:
`{kind, reason}` with `:login_gate`, `:consent_wall`, `:bot_check`, `:page_failed`,
`:harvest_failed`, carried on every failure entry and on `:search_unavailable`, and the rule
written down: a completed run with failures is a degraded round, a failed run with
`:search_unavailable` is an unavailable search.

**neuron-05, usage and an error class.** `get_run/1` returned no usage, tokens or cost, and
telemetry could not substitute because it undercounts sessions by half and by no constant
ratio. Model calls now record prompt and completion tokens against the model that served
them, browser sessions record seconds against the provider, both tagged with the run and
stage that spent them, in SQL because a stage is one Oban job in its own process. Totals
include the ingestion children a campaign dispatched. Failed runs carry `error_class`.

**neuron-12, leads without an observed contact channel.** Neuron discarded exactly the leads
the host is built to complete. `require_contact_channel: false` returns a matched person with
`observed_email: nil` and everything else unchanged, and the summary separates "no companies
matched" from "companies matched, no contact channel observed".

## What is deliberately not done

- **No prices.** Tokens and seconds are counted, not converted to money. That needs a rate
  table, and vendor prices in library code are a decision rather than an implementation
  detail.
- **No cost cap.** `error_class` reserves `:budget` so the host's enum is exhaustive, but
  nothing raises it. Usage is now recorded, which is what a cap would need.
- **`email` is not renamed.** `observed_email` is added alongside it. The rename is
  `neuron-06` and was not in this batch.
- **Nothing in Enma-Studios/neureni is touched.** That is another session's job.

## Findings for the owner, not fixed here

- **Google is bot-walled on Browser Use cloud IPs, on every query**, seven of seven in the
  acceptance run and four of four in the diagnostic. It contributes nothing in the host's
  configuration and is now honestly reported as skipped rather than silently empty.
  DuckDuckGo is walled intermittently, one query in six in the acceptance run and four of
  four an hour earlier. Yandex answered every time and carried both rounds. Whether Google
  stays in the default engine list is a decision, not a fix.
- **Six ingestion children failed on Dgraph write conflicts**, `Transaction has been aborted.
  Please retry`, when concurrent children upserted overlapping entities. The parent recorded
  each and continued, so the run survived, but evidence was lost. This is a retry gap in the
  graph write path and deserves its own issue.
- **The provider listing parameters are `pageSize` and `pageNumber`, not `limit`.** The spike
  handoff records that `/api/v4/browsers` ignores `limit` and returns ten rows, and concluded
  the endpoint truncates. It does not: it pages on `pageSize` and `pageNumber` and reports
  `totalItems`, and `limit` being ignored is what looks like truncation. Worth carrying back
  to neureni#40, whose cost workaround reads the same endpoint and undercounts for this
  reason.
