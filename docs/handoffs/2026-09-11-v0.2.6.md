# Handoff: v0.2.6

Three changes, all of them about a run telling the truth about itself.

| PR | Change |
| --- | --- |
| [#24](https://github.com/Enma-Studios/neuron/pull/24) | Capture the Brave fixture live and widen the entity decoder |
| [#25](https://github.com/Enma-Studios/neuron/pull/25) | Resolve browser configuration in one place and stop failing silently |
| [#26](https://github.com/Enma-Studios/neuron/pull/26) | Make `get_run/1` read-only and reconcile deliberately |

**Brave, verified.** The fixture that shipped in `v0.2.5` was built from the documented
response shape because no key existed. It is now a real capture, and the gated live test has
been run both ways: it passes with a key and fails loudly without one. Three things the live
API does that the documentation did not say are recorded in the handoff, including that Brave
rewrites the query and reports the rewrite, with an operator-heavy query returning far fewer
results than a plain one. **That is worth measuring before Brave is relied on for volume.**

`html_entities/1` decoded six entities, so anything else reached a lead as markup. It now
decodes a named table including the Latin-1 letters in European names, plus every numeric
entity, leaves anything it cannot decode exactly as written, and decodes in one pass rather
than turning `&amp;lt;` into a real tag delimiter.

**Browser configuration, single-sourced.** The reported symptom, children unable to browse
while their parent could, **did not reproduce**: a real child opened a session, and there is no
in-process path by which a child sees different configuration. The handoff says so plainly and
asks for the run IDs. What did get fixed is real anyway: resolution was copied into five
places; a partial `:browser` block from a host wipes `browser_use` underneath it; an
unconfigured browser now says where it looked; and a batch of children that all failed on
configuration now fails the run instead of finishing with "No companies matched the campaign
criteria", because a run that says it found nothing is a worse answer than one that says it was
never able to look.

**`get_run/1` no longer writes.** It reconciled as a side effect, so a host dashboard polling a
live run could fail it. Reconciliation moved to `reconcile_run/1`, which returns the same
snapshot. Three callers ask for it deliberately: `await_run/2`, `resume_run/1`, and the
campaign pipeline's collect stage, which would otherwise snooze against a discarded child until
the budget ran out.

## What a host has to decide

Polling no longer reconciles, so **something has to**. On a schedule, or on a run that has not
advanced for longer than its longest legitimate stage. Reading is free; noticing an abandoned
worker is now a deliberate act. `docs/operations.md` says so under "Polling a run".
